License, art and brand

This page answers three questions that are usually answered wrong, and by different files: what holds today, what is decided and has not yet been applied, and who needs to agree for the change to happen.

This page does not change the license

It documents. As long as LICENSE says what it says in the block below, that is what holds — here and in every other file in the repository. No file may declare the future license before LICENSE does.

What holds today​

The code is under the MIT License — that is what holds today, and the source is the LICENSE file at the root of the repository. No other file has authority over this.

The surfaces: everything that changes in the same commit​

Changing the license is not editing one file. Its name is repeated in every place where the project answers "what is the license?" — for the developer on GitHub, for the player in the footer, for the search engine in the JSON-LD, for an LLM in llms.txt. AGPL already appears in README.md (lines 329, 335), CONTRIBUTING.md (line 177), src/pages/sobre.astro (line 122), public/llms.txt (line 47) — as a notice of planned change, not as a declaration. That is the rule: no file may DECLARE AGPL before LICENSE says it.

Why this table is generated, and not a list

Two hand-written lists have already tried to enumerate these surfaces — the license section of README.md and step 3 of plans/08-RELEASE-PROFISSIONAL.md. Both of them forget the game's JSON-LD and the footer of this documentation. A list of where the license appears ages exactly like any other hand-written number: at the first commit that creates a new page. The list of surfaces to check is a human decision and lives at the top of tools/gen-docs.mjs; where each one names the license is measured on every npm run docs.

What is decided and pending: AGPL-3.0​

There is a recorded decision by the owner to migrate the code to AGPL-3.0. It has not been applied, and it reverses an earlier recommendation from the repository itself (plans/06 §1.2 argued for staying permissive because of Steamworks and of AI credit programs).

The reason for the turnaround is in plans/08 §3: the project intends to sell skins and maps, and selling items changes the threat model. The AGPL does not prevent selling — you sell the right of use — but it is honest about what it does not solve: anyone can publish a fork with the ownership gate removed, legally. That is the reason the real protection is server-side, not the license.

What has not been done yet, and is not a command line​

A license only changes retroactively with the consent of everyone who has already contributed. That survey is the blocking task, and it has a name and a size — measured, not estimated:

git shortlog -sne --no-merges origin/main   # who signs the published history
gh pr list --state merged --limit 50        # what came in, and from whom

On 2026-08-05, the published history (origin/main) has two third-party contributors with merged work:

WhoWhat came inWhere
daltonfontesthe fy_pool_day map ("Piscinão da Treta"), 1 commitis on this branch
William Oliveira (@woliveiras)the Godot desktop client, 13 commits, PR #14 merged on 18/07/2026main — not on this branch
The working branch's git shortlog does NOT enumerate the project's contributors

The people block in How to contribute measures HEAD, and HEAD is a branch. v2/alpha branched off main before the merge of PR #14, so William's 13 commits do not appear on it — and the doc was announcing three people in a repository that has four. For any decision about the license, measure against origin/main, not against the branch you are working on. See the Roadmap, section on the divergence between main and v2/alpha.

The repository is public and has stars (gh repo view --json stargazerCount), which means copies of the code under the current license already exist. That is irreversible: git history keeps the free version forever, and a fork made today remains under today's license.

The points that change together​

When the migration is applied, all of this goes in a single commit, announced:

  1. the LICENSE file;
  2. the badge at the top of README.md;
  3. the license section of README.md (a generated block — just run npm run docs);
  4. the term the contributor accepts, in CONTRIBUTING.md;
  5. the site footer (src/layouts/Layout.astro);
  6. the game's JSON-LD (src/pages/index.astro) and the /sobre page;
  7. public/llms.txt and the footer of this documentation.

The generated table above is the always-current version of this list — the line numbers come from it, and not from this paragraph. Half a license switch is worse than none, because each file starts answering something different to whoever asks.

The separation almost nobody knows about: code × art × brand​

This is the decision in plans/08 §3 that makes the rest possible, and it is three different licenses for three different things:

LayerWhat it isRegimeWhere it lives
Codeengine, base maps, UI, the entire harnessopen (AGPL-3.0, once applied)public repository
Paid artskins, maps and items that are soldits own license, proprietaryoutside the public repository, under authorization
Brand"CORO SOLTO: Treta Suprema", the canarinho, the logonot licensednobody's but the owner's

This is what makes it possible to sell skins without locking the code. The code stays open and auditable; what is sold is art, which was never under the code's license; and the name does not go along — a legal fork of the engine is not CORO SOLTO, because the brand was not licensed.

This is irreversible once the first paid art exists

The character GLBs are already in the public repository (the count is in the generated block of Getting started). If one of them becomes a paid item, relicensing is retroactive and git history keeps the free version forever.

The decision about where paid art lives has to be made BEFORE the first paid art exists. After that, the cost is not editing a LICENSE: it is accepting that the sold item has already been distributed for free.

And the uncomfortable truth, written down so it is not rediscovered every round: the player can always make their own screen show any skin, and trying to prevent that costs weeks and does not work. The fraud that matters is obtaining the file without paying and showing up with it to the others — and that one is server-side, like the entitlement, which lives in Postgres under service_role. Spending effort on the client is spending it in the wrong place.

Third parties this project uses​

  • Three.js — MIT (© Three.js authors), vendored in public/vendor/.
  • Audio — the pack is not versioned; the voices and memes have uncertain rights. CS 1.6 sounds are the property of Valve and are not distributed here. Without the pack, the game uses synthesized sounds and runs normally.
  • Independent parody, with no affiliation with Valve. Counter-Strike is a trademark of Valve Corporation.

AI-generated assets (mint.gg, Tripo3D, Meshy, OpenRouter) enter the repository as a result, with the provenance record in mint-assets.json — see Stack and tools.

If you are going to contribute​

The term that holds is in CONTRIBUTING.md, and it is the source — this page does not repeat it. The operational summary: you license under whatever license LICENSE says at the moment of your PR, the planned migration will come in a single, announced commit, and if that is decisive for you, ask before opening the PR.
